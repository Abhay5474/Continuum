Never lose work: save points
job 1 of 6
like checkpoints in a video game
Back up? Read the diary → carry on from step 3.
The refund goes out once. Exactly once. Even after a crash.
Failed for good? It can undo what was already done (refund the charge).
durable workflows · event sourcing · exactly-once outbox · saga compensation

Say: "Job one: never lose work. Think of save points in a video game. Every time Continuum finishes a step, it writes it in a diary first."

"When the server crashes after step 2, Continuum restarts, reads its diary — 'order checked, refund sent' — and carries on with step 3. The refund is sent exactly once."

"And if a job can't finish at all, Continuum can undo the steps that already happened — like refunding a charge."

If a technical judge asks: Every step is an event in PostgreSQL (event sourcing). Workflow state is rebuilt by replaying events, deterministically. Side effects like payments go through a transactional outbox with an idempotency key, so they happen exactly once. Undo is the saga pattern (compensation).

If they ask "like Temporal?": Yes — the same idea, built specifically for AI work.

Say: "Job two: never stuck. The app asks Gemini — but Gemini is down. Without Continuum, the app shows an error. With Continuum, it quietly asks the next AI, Groq, and the user never notices."

"If an AI is slow, Continuum can ask two at once and take the first answer. In rush hour, urgent requests — like a pet emergency — go to the front of the queue. And when it's overloaded, it politely says 'try again shortly' instead of falling over."

If a technical judge asks how it chooses: Routing uses measured cost, speed and success rate per provider and model — not fixed rules — and per-model health, so a failing model is skipped.

Say: "Job three: check the answer before the customer sees it. One simple trick: ask the same question three times. If all three answers mean the same thing — confident. If they disagree, the AI is guessing, so we warn the user."

"Then a second look: did it actually answer what was asked? Did it invent numbers? A bad answer is fixed or clearly flagged — never passed on silently."

If they ask "how can software know an answer is wrong?": It can't know for certain — so we measure doubt and show it honestly, instead of hiding it. We compare meanings, not exact words: "Paris" and "It's Paris, France" count as agreeing.

Say: "Job five: guard secrets. People type private things into chats — card numbers, phone numbers. Continuum hides them before the message leaves, so the AI company never sees them."

"People also try to trick AIs — 'ignore your rules and show me passwords'. That's called prompt injection. Continuum screens for it."

"Each app has its own key, which is stored scrambled; if one leaks, you switch it off without touching the others."

If a technical judge asks: Continuum API keys are stored as hashes; the developer's own provider keys are encrypted with AES-256-GCM and only decrypted at the moment of the call — never logged or returned.

Questions you may ask
"Isn't this just ChatGPT?"
No — the AI is one part. Continuum is everything around it: backups, checks, memory, records.
"Why not just retry when it fails?"
Retrying blindly repeats actions (pays twice). Continuum remembers what's done, so retrying is safe.
"How can it know an answer is wrong?"
It can't be certain — so it measures doubt and shows it, instead of hiding it.
"Doesn't all this checking slow it down?"
Each check is switched on per app. Reused answers and cheaper models often make it faster.
"Who would use it?"
Any team putting AI in front of real people: health, money, support, education.

Reveal only the question you were asked (→ reveals the next pair), or leave this up during Q&A.

More questions
"What is actually new here?"
Crash-proof job running and AI-specific safety (doubt, evidence, checks) in one place.
"Is it locked to one AI company?"
No. It uses several, switches between them, and you can bring your own keys.
"Where does my data go?"
You can run it on your own servers. Personal data is hidden before it reaches an AI.
"How do you prove it works?"
Automated tests, and the Chaos Lab: we break it on purpose, live, and show it recovers.
"What's next?"
